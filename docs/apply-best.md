# Apply-best deployment

`apply-best` is a dedicated, recoverable champion deployment workflow. `apply-best-validate` checks champion provenance, target safety, recovery state, and timing. `apply-best-prepare` creates the singleton ledger without changing PostgreSQL. `apply-best-recovery-test --deployment-id <id> --confirm-transient-change` performs a transient apply/restart/verify/rollback cycle. `apply-best-status --deployment-id <id>` checks durable state against the target. `apply-best-activate` persists the specific operator decision before mutation; `apply-best-rollback` restores the captured pre-activation snapshot and verifies health. Use command `--help` for the complete required decision and hash arguments.

On the recorded host D070 recovery-tested champion E, then D071 persistently activated deployment `c8e561f0-fce1-5c97-b2e8-d3a5bf3d84b2` under explicit operator authorization. All eight settings and target health passed the post-activation check. The recorded 32-second activation and 34-second emergency-rollback estimates are measured operator estimates, not general outage guarantees. The snapshot and receipt are in [submission release provenance](../experiments/thesis/provenance/submission-release.md). Migration checks do not activate or roll back this deployment.
