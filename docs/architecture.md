# Architecture

`src/charmdb` is the sole application package. `cli.py` retains the entry point while `cli_commands/` registers runtime, calibration, primary, multi-fidelity, confirmation/deployment, and evidence commands. `protocol.py` validates frozen manifests and `paths.py` resolves historical logical path names. `restore/` holds preflight, archive, capability, fingerprint, and candidate-restore logic. `optimization/` holds the eight-knob design and Bayesian proposal logic. `campaigns/` creates and resumes immutable schedules. `analysis/` authenticates stage outcomes; `reporting/` renders deterministic tables, figures, and indexes. `apply_best.py` is a separate recoverable deployment workflow.

The control PostgreSQL database is distinct from the Docker Compose target. Forward-only SQL migrations persist campaigns, slots, trials, attempts, leases, transitions, markers, snapshots, decisions, and deployment state. The worker leases durable trials, restores the candidate dataset, applies bounded settings, verifies active values after restart, measures with `pgbench`, authenticates raw artifacts, and rolls back or records the safe state. Stage runners reconcile attempts and rebuild optimizer observations from eligible persisted evidence.

Only `HEALTH_CHECK`, `V2_BASELINE_BENCHMARK`, `V2_TUNED_BENCHMARK`, and `V2_SATURATION_PHASE1` workflows are executable by the canonical worker. `V2_*` values, `experiment_v2_*` tables, profile identifiers, deterministic seeds, artifact markers, and frozen manifest names retain their spelling because changing them would break persistence and evidence identity. Historic index/arm/API execution surfaces are removed; unexpected indexes remain a target-safety check.
