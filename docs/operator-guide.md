# Operator guide

Install with `make install`; configure `.env` from `.env.example` with distinct control and target databases and a separate `CHARMDB_ARTIFACT_DIR`. `make up` starts the pinned Compose target and applies control migrations. `make smoke` checks connections; `make down` stops the target. `make seed-scale10` is a small local setup command, not the frozen scale-500 thesis profile.

Use `uv run charmdb --help` and each command's `--help` for exact arguments. `bootstrap-preflight`, `restore-capabilities`, and stage `*-validate` commands check readiness before creation or execution. `primary-*-history`, `primary-*-analyze`, `primary-final-report`, `evidence-manifest`, and `evidence-ledgers-export` inspect or render authenticated evidence. `apply-best-status --deployment-id <id>` audits recorded deployment state against the live target; `apply-best-rollback` is the dedicated emergency rollback path. Activation and rollback mutate the target and require the workflow's internal authorization and state guards.

The recorded D071 deployment is `c8e561f0-fce1-5c97-b2e8-d3a5bf3d84b2`, activated under explicit operator authorization. Its snapshot and recovery details are preserved in [submission-release.md](../experiments/thesis/provenance/submission-release.md). Do not use this identity on a fresh control database. On a new host, preserve old evidence, initialize fresh state, validate restore capability, and recapture baseline/default evidence before any new comparison.
