# Operator guide

Install with `make install`; configure `.env` from `.env.example` with distinct control and target databases and a separate `CHARMDB_ARTIFACT_DIR`. `make up` starts the pinned Compose target and applies control migrations. `make smoke` checks connections; `make down` stops the target. `make seed-scale10` is a small local setup command, not the frozen scale-500 thesis profile.

Use `uv run charmdb --help` and each command's `--help` for exact arguments. `bootstrap-preflight`, `restore-capabilities`, and stage `*-validate` commands check readiness before creation or execution. `primary-*-history`, `primary-*-analyze`, `primary-final-report`, `evidence-manifest`, and `evidence-ledgers-export` inspect or render authenticated evidence. `apply-best-status --deployment-id <id>` audits recorded deployment state against the live target; `apply-best-rollback` is the dedicated emergency rollback path. Activation and rollback mutate the target and require the workflow's internal authorization and state guards. The supplemental `h25-validate`, `h25-create`, `h25-run`, `h25-history`, `h25-analyze`, `h25-export`, `h25-report`, and `h25-abandon` commands drive the three-arm H25 block (H25, DEFAULT at center, champion E). Every candidate restore requires the target to be at the frozen preflight default settings, so an active champion deployment must be rolled back with `apply-best-rollback` before `h25-run`; `h25-validate` reports `target-settings-differ-from-canonical-preflight` and `h25-run` refuses to create a slot until it is. `h25-abandon` retires a live block that has no valid observation so a superseding block can be created. Run `apply-best-status` after the block; re-activating the champion afterwards is a new prepare, recovery-test, and activate cycle with its own authorization.
